# Security model

Resource IDs are bearer capabilities and are embedded in public URLs. Anyone who learns a URL therefore has the ID needed to read, update, or delete that resource; there is no separate edit token. IDs must not appear in logs in full.

Resources are public but non-indexed. `X-Robots-Tag` and Markdown robots meta ask cooperative crawlers not to index or archive content. This is not authentication, authorization, revocation distribution, or a confidentiality boundary. Never publish credentials, API tokens, cookies, private source, personal data, regulated data, or other sensitive material.

## Whiteboards and creator context

Every new or updated Markdown or HTML resource contains two artifacts: source and creator context. The context is intended to summarize goals, decisions, assumptions, and open questions. It must not contain hidden reasoning, credentials, unrelated personal data, sensitive data, private source, or raw tool output.

The main browser presentation renders only the source. When the local-agent viewer is enabled, its Page context disclosure lets the reader inspect the exact Markdown or HTML source and creator context before sending a message. The format-specific machine GET routes and `agent-whiteboard --json get markdown|html ID` likewise return both exact strings. Anyone holding the public URL can recover its ID and use that retrieval route. Context therefore has exactly the same bearer-capability exposure and expiration/deletion lifecycle as source; it is not private merely because it is absent from the main rendered document.

Markdown is rendered client-side by bundled JavaScript. Raw Markdown HTML is disabled, links and generated SVG are sanitized with DOMPurify, Mermaid uses strict security settings, and no CDN is needed. The JSON source envelope escapes script-closing sequences. These controls reduce injection risk but do not make publication of secrets safe.

## Standalone HTML and images

Standalone HTML remains trusted active content, but its public capability URL returns an application-controlled wrapper rather than submitted bytes. The wrapper contains exactly one `credentialless` iframe with `sandbox="allow-scripts"` and `referrerpolicy="no-referrer"`. The capability's `/content` route always returns exact submitted bytes. With Page Agent enabled, the iframe instead uses `/rendered`, which injects the bundled bridge immediately after the exact source `<head>` start; historical source that cannot be injected safely falls back atomically to exact unbridged bytes and chooser-only behavior. New create/update requests require a safe head-first document. Both child routes independently apply a CSP sandbox without `allow-same-origin`, plus `connect-src 'none'`, `frame-src 'none'`, `form-action 'none'`, and restrictive resource directives.

Bundled trusted chrome owns theme state, broker transport, canonical source/component indexing, context, activation, and the shared drawer above the iframe. The rendered-child bridge is a bounded coordination channel, not a trusted DOM boundary. The parent sends only an epoch plus component IDs/types (and revision-bound locate requests); it sends no source, labels, source excerpts, creator context, resource or broker data, credentials, preferences, or submission intent. The only child-to-parent influence is a one-way flow of untrusted ready/clear/candidate geometry hints. The parent accepts them only from the current iframe `event.source`, with the current unpredictable epoch and exact bounded frame schema; it rejects transferred `MessagePort`s, unknown IDs/types, stale epochs, malformed geometry, and extra fields. It never reads the live child DOM and resolves every label, source excerpt, anchor, and activation against its inert exact-source index.

Inline publisher scripts can run, observe or interfere with bridge traffic, withhold candidates, send misleading geometry, self-navigate away from the bridge, or imitate candidate messages. They cannot create a canonical component, add a message token, choose submission content, or reach the broker; the parent-owned chooser remains available without child cooperation. Opaque-origin scripts cannot read parent content, publishing-origin cookies or storage, load child frames or remote subresources, submit forms, open popups, initiate downloads, navigate the top page, or make fetch, XHR, WebSocket, or authorized loopback-broker connections.

Sandboxing does not generically prevent a script-capable child from navigating itself. Under the supported wrapper, the outer `frame-src 'self'` policy limits that navigation to the publishing origin, while `credentialless` and `no-referrer` prevent publishing-origin cookies and the capability Referer from accompanying it. Submitted code can still deliberately encode its `/content` capability URL into a permitted same-origin navigation, exposing it to publishing-origin request handlers or logs. Cross-origin child navigation is additionally blocked by the wrapper's current CSP, but direct top-level navigation to `/content` is not the supported entry point and does not gain the wrapper's destination restriction. Treat self-navigation capability disclosure as an accepted risk and publish only HTML you trust.

Image uploads accept PNG, JPEG, GIF, and WebP only after signature detection and format-specific configuration validation. SVG is rejected because it can contain active content. Responses use `nosniff`, a detected media type, inline filename, no-store caching, and `noimageindex`.

## Local browser agent

The optional Page Agent for Markdown and HTML talks only to the configured decimal port on literal `127.0.0.1`; it never scans hosts or ports. Before explicit Connect consent, it may issue only the bounded status request. Selecting Pi, Codex, or Cursor is local and silent. Connect carries resource metadata and the context digest but no source or creator context. The first contextual message sends both complete artifacts together; later messages omit them until an observed resource revision requires a complete replacement. Codex and Cursor receive the complete canonical context envelope as user-message content, not as replacement system instructions. Submitting detaches the exact payload from the editable composer immediately and shows it as pending. A definitive pre-acceptance rejection restores it only into an unchanged empty draft slot; otherwise Page Agent retains a **Not sent** item with an explicit restore action. A disconnect changes unresolved delivery to **Confirming delivery** and reconciles stable turn and message IDs against authoritative queue, active-work, snapshot, and bounded timeline-page evidence. Page Agent concludes that a turn was not written only after a fresh snapshot and a terminal history page both prove absence; if bounded history cannot prove absence, delivery remains indeterminate. Failed history reads reconnect and retry without resubmitting. A disconnect or uncertain delivery never automatically resubmits a model turn.

For Markdown, inline text and section references carry bounded quoted/source Markdown plus revision-bound structural anchors. Adding a Mermaid diagram uses the same section reference contract with its exact fenced source; rendered SVG and pixels are not included or staged. For HTML, component references carry a bounded exact-source excerpt and parent-derived element ID/tag/ordinal for a labeled component in the inert source index. All references are untrusted message content, not authority, executable instructions, or replacements for the complete exact source and creator context. The broker rejects references whose resource identity, update time, or context digest does not match the current complete context. Composer tokens are atomic projections backed by the parent's internal model, so pasted token-shaped HTML and child messages cannot forge a reference. Multiple tokens retain their order among reader text, and source navigation is enabled only while the referenced revision remains current.

An HTML `image` component may stage one optional private visual only when exact source contains exactly one unambiguous embedded base64 PNG, JPEG, GIF, or WebP image and the connected model supports images. The parent never captures the runtime frame. SVG/canvas renderings, remote or blob URLs, responsive alternatives, runtime-mutated pixels, video/audio, live values, other component kinds, and unavailable image capability remain semantic exact-source references. Staged bytes follow the same loopback authorization, validation, purpose binding, limits, provider policy, and lifecycle as other inline images.

Pi, Codex, and Cursor keep independent conversations, lifecycle state, pending requests, and archives for a whiteboard. Pi retains its follow-up queue. Codex and Cursor use preserve-draft busy behavior: while work is active, the editable next draft remains browser memory and is not submitted until idle. Stop, queue changes where supported, new conversation, and restore apply only to the selected provider. Archive deletion is unavailable for Cursor and remains provider-specific where supported. Switching providers does not interrupt the inactive provider, which may continue responding.

Page Agent image bytes travel from an authorized viewer directly to the literal-loopback broker. They are never sent to the publishing server, turned into public image capabilities, placed in browser preferences, or included in WebSocket commands and replay events. Upload, preview, and unsent deletion require the exact admitted Origin plus the attached client and conversation IDs; upload also binds the selected provider. Opaque image IDs are bearer-like within that attached conversation and must not be logged or shared.

Selecting a rendered image reads only an embedded base64 PNG, JPEG, GIF, or WebP or a same-origin resource. Same-origin reads omit credentials and referrers, disable caching, reject redirects, and are revalidated by the broker. The staged image is purpose-bound as an inline reference and cannot be substituted for an ordinary attachment during atomic claim. Removing its composer token releases unclaimed staging; queued edits release only selected images no longer present.

The broker detects and validates the configuration of PNG, JPEG, GIF, or WebP content and rejects SVG, malformed images, and other file types regardless of filename or browser media type. Fixed safeguards allow 8 images, 10 MiB each, 20 MiB per draft/turn, and 512 MiB retained per conversation workspace. Unclaimed staging expires after 15 minutes and is swept on startup and periodically. Claimed originals remain in the owner-only conversation workspace so queued turns, history previews, and native session resume continue to work; removing a queued item or receiving a definitive pre-acceptance rejection releases its images, while an uncertain provider outcome retains them conservatively. Where archive deletion is supported, deleting a conversation archive removes its workspace and images.

Provider paths and bytes never enter browser protocol events. Pi reads each validated private file immediately before submission and base64-encodes it into native image content; the user's Pi image settings remain authoritative and may still block reading. Codex receives the validated absolute private path through native `localImage` input, so accepted originals must remain available for the conversation/archive lifetime. Cursor images must be validated workspace files; the Cursor adapter opens them with Unix descriptor and binding checks and then sends their bytes as base64 standard ACP image blocks. All adapters preserve the configured model, authentication, approval, sandbox, and image policy.

After explicit connection to a provider with a native skill catalog, Page Agent may disclose enabled skill names, bounded display names/descriptions, scope, selection limit, and session-opaque IDs to the trusted page origin. Cursor exposes no native skill catalog or manual compaction. Pi permits one selected skill and restores only the canonical envelope's sole outer terminal LF after native command expansion; every length-delimited HTML, creator-context, source, and reader-content field remains exact. Skill bodies, native paths, load errors, dependencies, icons, URLs, and default prompts remain adapter-private and are never persisted in browser storage or durable broker state. Manual-compaction rows are actor-lifetime UI only and are not reconstructed after broker restart.

The browser accepts only the versioned, strictly validated broker event schema. Provider-native session, thread, turn, compact-turn, item, message, tool, request, and elicitation IDs, credentials, hidden reasoning, and raw ACP or App Server frames are never browser events or log evidence. Standard Cursor tool activity is normalized, bounded, and redacted through the shared provider-neutral UI. For Codex, normalized and bounded activity can include commands, working directories, paths, diffs, tool names, arguments, output, results, and failure summaries supplied by App Server. Treat all surfaced details as sensitive local information. Assistant Markdown is sanitized and automatic-fetch media is removed. A generic responding indicator exposes lifecycle state, not model reasoning. Pi configured tool and permission activity is currently surfaced only as generic sanitized activity and does not expose attempted tool names, arguments, payloads, or output.

Provider interaction requests are relayed through bounded shared cards, including standard Cursor command/file permission requests, stable App Server approvals/MCP elicitation, and Pi select, confirm, input, and multiline editor requests. The first valid response across attached tabs wins atomically. For Cursor, success means the complete local ACP response was written; for Pi, it means the complete local response record was written. Neither proves provider consumption. `NotWritten` is the only retry-safe delivery result. `Indeterminate` fails closed and is never replayed automatically. Page Agent never invents an approval when the effective policy does not request one. App Server's experimental `request_user_input` remains disabled.

Browser storage is limited to theme, pane-open state, the decimal loopback port, a canonical integer pane width from `360` through `720`, the selected provider (`pi`, `codex`, or `cursor`), and provider-scoped last-accepted bounded settings for new conversations. The effective width may be temporarily clamped for the viewport without replacing the saved preference. Capabilities, resource metadata, Connect consent, messages, context, conversation IDs, pending requests, decisions, provider output, credentials, and hidden reasoning are never browser preferences.

Chrome Local Network Access is an additional browser permission, not broker authorization. The broker binds only to IPv4 loopback, requires an exact Host and canonical Origin, reloads configured HTTPS trust for admission, omits credentials and referrers from browser requests, and applies exact-origin CORS. Standalone HTML has an opaque origin and cannot obtain this authority.

Canonical HTTP origins on literal `127.0.0.1`, with no port or a valid non-default port, are automatically admitted without a configured trust entry. `localhost`, other IPv4 loopback addresses or spellings, IPv6 loopback, explicit default port 80, and remote HTTP origins remain rejected. This is an intentional local-development trust boundary: any browser page served by any local process from literal `127.0.0.1` can call the broker directly and is not forced to use the viewer's Connect control. Run and open only trusted local servers and content. Configured non-loopback trust remains exact-origin HTTPS only.

## Configuration and origin allowlist

Trusted origins must be exact HTTPS origins. The CLI rejects paths, queries, fragments, user information, wildcards, and HTTP. Exact origin configuration does not add authentication to whiteboard resources.

On macOS, the managed daemon records the absolute Agent Whiteboard executable, selected/default Agent Whiteboard configuration path, resolved Pi, Codex, and Cursor executable paths when available during installation, and a standalone runtime `PATH`. The runtime path contains sanitized absolute entries from the installing process plus common system and package-manager locations; relative, empty, unclean, duplicate, and control-character entries are omitted. The daemon does not source shell startup files or persist other ambient variables. Provider-specific persisted data remains limited to resolved executable paths: it does not copy Pi, Codex, or Cursor configuration, authentication, credentials, or raw launchctl output, and it never edits `~/.codex/config.toml` or Cursor authentication, configuration, or shell state. `agent serve --daemon` installs/updates and starts the service; `stop` unloads it but retains the plist, and `uninstall` removes it. Linux rejects managed daemon operations with foreground guidance. Authenticate with each provider's native login, including `cursor-agent login` for Cursor. Agent Whiteboard never invokes ACP `authenticate`, opens Cursor's login browser, receives credentials, or captures or persists provider credentials.

## Provider trust boundary

Whiteboard source, creator context, metadata, and reader messages are untrusted model input. Pi, Codex, and Cursor run with the user's normal effective provider home and inherit the configured model, tools, extensions, MCP servers, apps, rules, hooks, skills, project instructions, approval policy, sandbox, project trust, and other settings unchanged. Agent Whiteboard does not create a production provider home, edit provider configuration or shell state, or add per-turn model, approval, sandbox, tool, rule, hook, MCP, or project-trust overrides. Untrusted content can therefore activate the user's native Cursor tools, rules, hooks, and MCP under Cursor's native policy; trusting the publishing origin is not a provider sandbox.

One lazily started App Server process is shared by loaded Codex conversations, so an App Server failure can interrupt all active Codex turns. Cursor uses stable standard ACP v1 by launching `cursor-agent acp`; it requires negotiated ACP v1 plus stable `session/list` and `session/load` and fails closed when either is missing or incompatible. Each loaded Cursor conversation has one child process, which bounds conversation failures; readiness may additionally use a transient non-conversation probe. Resume proves the durable native session is still listed before loading it. If an uncommitted, prompt-free native session is definitively absent, Agent Whiteboard may create a replacement in the same workspace and atomically update only its native reference, preserving page observation, settings, and archives; committed or indeterminate sessions are never replaced or replayed automatically. Known Cursor adapter-runtime failure artifacts are converted to sanitized terminal failures after acceptance, without exposing native diagnostics or replaying the prompt. Agent Whiteboard does not use Cursor-private `cursor/*` methods, Cursor-private files or storage, ACP client tools, filesystem or terminal capabilities, or arbitrary configuration options.

The effective provider approval and sandbox policy, not Page Agent or origin trust, authorizes tool execution. Prompt injection in published content can therefore cause tool activity or approval requests. If the effective approval policy does not request confirmation, Page Agent does not add one; in particular, permissive native settings can allow actions within the effective sandbox without a browser prompt. A browser admitted to the local broker can see bounded activity for its attached conversation.

This initial non-public deployment explicitly defers tool allowlists, content-only execution, per-whiteboard filesystem roots, container or VM isolation, experimental permission profiles, and a stronger cross-agent sandbox. These are trust risks, not security guarantees. Use suitably restrictive provider configuration and sandboxing for the content you open, and do not treat origin trust or `agent.default_access` as a provider tool boundary.

Cursor history is reconstructed only from validated exact envelope replay before a successful `session/load`, using broker-safe IDs and timestamps. A validation failure, load failure, disconnect, uncertain write, or reconnect never automatically resubmits a turn.

Configuration files must be regular non-symlinks and must not be writable by group or others. On macOS and Linux, trust operations additionally require the immediate parent to be a non-symlink directory that is not writable by group or others; edits are locked, written to `0600` temporary files, synced, and atomically renamed. See [configuration](configuration.md) for the complete permission and platform contract.

## Non-leakage and filesystem boundary

The service validates multipart fields, independent exact size limits, capability IDs, filesystem containment, regular files, and symlink safety. Logs avoid request bodies, whiteboard source, creator context, and full capability IDs. Operational logs and metrics should keep the same rule. Stable HTTP/CLI errors sanitize internal causes and do not echo source, context, raw multipart data, or filesystem paths.

A failed create can exceptionally return a resource capability alongside a sanitized error when rollback cannot prove absence. Preserve and explicitly check/delete that ID rather than logging it broadly. Ordinary failed creates expose no generated capability.

Use TLS and appropriate network access controls when serving beyond localhost. TLS protects capabilities in transit but does not turn a shared capability URL into identity-based authorization.
