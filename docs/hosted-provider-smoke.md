# Optional hosted-provider smoke test

This procedure is manual and optional. It uses the operator's native Pi and Codex configuration and is excluded from CI because CI must not use public networks, hosted services, or credentials.

1. Use disposable low-cost provider accounts and a non-sensitive Markdown fixture and creator context. Do not use production capability URLs, private source, personal data, or secrets. Use a restrictive Codex approval policy and sandbox suitable for untrusted whiteboard input.
2. Authenticate with Pi and Codex through each provider's native CLI flow. Do not pass API keys or tokens through Agent Whiteboard flags, environment variables, prompts, or logs.
3. Enable `viewer.local_agent.enabled`, add the exact HTTPS publishing origin with `agent-whiteboard agent trust add`, and start the publishing server and `agent-whiteboard agent serve`.
4. In current Chrome, open the Markdown capability, grant Local Network Access if prompted, inspect the Page context disclosure, and switch between Pi and Codex before connecting. Confirm that selection alone produces no hosted request and sends no page content.
5. Confirm the viewer and broker negotiate local API version 4 and WebSocket subprotocol `agent-whiteboard.v4`. If they are incompatible, deploy both together and restart the foreground broker or managed daemon; do not continue with mixed versions.
6. Select Pi and connect. Drag across part of a paragraph and use **Add to message**, add a heading section, and type text before, between, and after both inline tokens. Send it and confirm the displayed and provider-received message preserves that exact order while the provider turn also contains the complete Markdown/context envelope. Activate a sent token and confirm the viewer returns to the matching source.
7. With a disposable PNG or JPEG, exercise multi-file selection, image paste, remove, and an image-only submit. Also select a rendered same-origin image with **Add image** and confirm it appears inline rather than in the attachment tray. Confirm preparing/ready previews, the sent preview, a queued image preview during an active response, and restored history after reconnect. If the selected model reports no image support, confirm both image controls are unavailable while text remains usable instead. Do not weaken Pi's native image policy for this check.
8. Select Codex and confirm Pi's transcript remains intact while Codex starts with its own conversation and archives. Connect, open the composer pill, and choose a visible model, one supported effort, and Standard or Fast speed. Confirm incompatible choices are disabled rather than silently repaired. Send a different non-sensitive message plus a disposable image. Confirm Codex receives the complete canonical envelope as user-message content and the exact selected tuple, where Standard sends native `serviceTier: null` (reported as `default`) and Fast sends `serviceTier: "priority"`. Confirm image availability follows the selected model and no private path appears in the browser.
9. If the effective Codex configuration makes a harmless command, file change, permission request, or MCP elicitation available, exercise one request without using sensitive data. Confirm bounded tool activity appears, the interactive response reaches App Server, and a second attached tab becomes read-only after the first valid response wins. Do not expect a Page Agent prompt when the effective approval policy does not request one.
10. Do not test `request_user_input` as part of this stable smoke test. It is an experimental App Server API and Agent Whiteboard leaves `experimentalApi` disabled.
11. With a disposable non-sensitive native skill, type `$`, select it, and submit it alone and with text. Confirm native behavior and verify no skill path or body appears in browser frames or DOM. Remove or disable it natively, refresh the catalog, and confirm a retained stale token is marked unavailable and the draft is not submitted.
12. Run exact `/compact`, confirm `Compacting context…` then `Context compacted`, and repeat with Stop to confirm `Stopping…` then `Compaction stopped`. During an active Codex turn, prepare a next draft and press Enter; confirm no follow-up command or queue row appears, Stop preserves the draft, and Pi still queues normally under the equivalent Pi flow. During active Pi and Codex work, confirm Escape performs the same interruption as Stop without closing Page Agent.
13. After one accepted Codex turn, reload and open a genuinely new whiteboard from the same publishing origin. Confirm the last accepted tuple initializes it, while an existing or restored conversation retains its own effective native tuple and an unsent menu edit disappears on reload. Send a continuation for each provider and confirm unchanged page context is not resent. Interrupt a separate test turn and confirm it is not automatically replayed. A Codex App Server failure may interrupt every active Codex turn, but Pi remains independently available.
14. Exercise New, archive restore, and archive deletion for each provider only with disposable sessions. Confirm that Codex New uses the currently visible pill, archives remain provider-specific, restored Codex settings override browser preference, attachment previews restore, and archive deletion removes the disposable image workspace before removing local test state.
15. Stop the broker, delete the disposable whiteboard and local test sessions, and remove the test origin from the trust list if it is no longer needed.

Do not capture provider request bodies, auth files, transcripts, capability IDs, model output, tool details, or approval payloads in shared logs or bug reports. Record only sanitized pass/fail observations and version information. This smoke test does not establish a content-only boundary: tool allowlists, per-whiteboard filesystem roots, and a stronger cross-agent sandbox are deferred.
